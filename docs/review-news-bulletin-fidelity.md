## 1. Verdict

The extractor reads this page's **typography and colours correctly**, but it does not
reconstruct the **layout, the visibility state, or the background stack**. Of the 34 text
nodes the browser renders, 33 are found by the extractor, but **only 1 lands within 1 % of
its real box**, and the `.t` layers that the page hides until their `data-s` are emitted at
`opacity: 0` — invisible for the entire reel, keyframes included.

The attached screenshots show exactly this: the three preview cards render the photo (and,
in card C, the two elements that carry inline `opacity:1`) but no reel copy; the layer list
on the right is full of amber boxes at `x -103.4` and `y 82` with `h 100`.

Root cause is structural, not a handful of typos: the Python file re-implements a *subset*
of CSS with **no layout engine**. These pages are built with `container-type: size`,
`cqw` units, absolutely positioned blocks, `bottom`/`right` anchoring, shrink-to-fit inline
blocks, padding, content-driven heights, `overflow` clipping and a two-state animation model
(`.t` / `.on`). Every one of those is currently missing or wrong.

```bash

  --html "html-examples/Singl-end · news bulletin reels.html" \

# score the current extractor against that fixture

  --fixture tests/fixtures/news-bulletins-chrome-boxes.json \
  --html "html-examples/Singl-end · news bulletin reels.html" --verbose

# (check-html-parse.py runs the extractor itself; --strict exits 1 on failure)
```

Current output of the checker:


`measure-html-chrome.py` loads the page in headless Chrome, disables transitions, adds
`.on` to every `[data-s]` element (so the element is measured in the state it is actually
seen in), and records per element: box in % of the stage, computed typography/colour/
transform, direct text, **and the nearest clipping ancestor**. It needs only a Chrome binary
(no Python packages, no Node). The fixture is a snapshot of that output, so fixes can be
regression-tested.

## 3. What this page actually is

Three `.stage` blocks (`n1`, `n2`, `n3`), each `aspect-ratio: 9/16`, `container-type: size`.
All sizes are `cqw` (1 % of stage width). The animation model is:

```css
.t  { position: absolute; opacity: 0; transform: translateY(4cqw); transition: … }
.t.on { opacity: 1; transform: none }          /* the state the viewer sees */
.sl { transform: translateX(-110%) }  .sl.on { transform: none }
```

and the page JS toggles `.on` per element from `data-s` / `data-e` (10 s loop):

```js
s.querySelectorAll('[data-s]').forEach(e =>
  e.classList.toggle('on', t >= +e.dataset.s && t < +e.dataset.e));
```

So `data-s`/`data-e` are **hard visibility windows**, and the resting geometry is the
`.on` state — not the CSS default. That single fact invalidates most of the current output.

## 4. Findings

Severity: **P0** = output is wrong/unusable, **P1** = visible fidelity loss, **P2** = polish/plumbing.

### P0 — blockers

#### F1. The pre-animation state is treated as the resting state
`.t { opacity: 0; transform: translateY(4cqw) }` and `.sl { transform: translateX(-110%) }`
are baked into every layer, because `computed()`/`inherited()` never consider the `.on`
state that defines the element's real geometry.

Evidence (parsed → truth):

| layer | parsed | truth |
|---|---|---|
| `.tg` (BREAKING) | `-103.40, 75.25, 94.00, 2.56` | `5.00, 52.08, 30.25, 3.41` |
| `.hd` (Cyclist…) | `-103.40, 77.81, 94.00, 8.51` | `0.00, 55.49, 94.00, 15.56` |
| `.lv` (LIVE) | `5.00, 7.31, 100.00, 3.10` | `5.00, 5.06, 22.02, 3.91` |

and the generated composition has `"opacity": 0` with keyframes that fade **to** 0:

```
html-01-shape-banner  kf [(0,0.01),(300,0.01),(600,0.0),(1900,0.0),(2200,0.01)]
html-02-breaking-news kf [(0,0.01),(300,0.01),(600,0.0),(1900,0.0),(2200,0.01)]
html-18-shape-bar     kf [(0,0.01),(2400,0.01),(2700,0.0),(9200,0.0),(9500,0.01)]
```

The BREAKING NEWS banner, LIVE badge, top-right kicker and the ticker bar are **never
visible** in the output. `FADE_MS` also imposes a 300 ms fade the page does not have.

**Fix**
- Add an *active selector* pass to `computed()`: for any node with `data-s`/`data-e`,
  additionally apply rules of the form `<same selector>.on` (and `.on` on each of its
  classes). Same for `:hover`-style variants we cannot know — only `.on` is safe.
- Drop `transform` values that exist only in the off state (`translateY(4cqw)`,
  `translateX(-110%)`), and take `opacity` from the `.on` state.
- Emit keyframes from `data-s`/`data-e` windows (see F11), not from a blanket fade.
- Code: `computed()` (L381), `inherited()` (L403), `_apply_translate()` (L522), `make_layer()`
  opacity (L897), `_timing_keyframes()` (L1115).

#### F2. `bottom` is used as `top`, `right` is used as `x`
`_partial_box()` does `y = 100 - bottom` and `x = 100 - right`, i.e. it treats the *edge*
offset as the box origin, and leaves the width at the parent's width.

| layer | parsed | truth |
|---|---|---|
| `.l3` block | `0, 75.25, 94, —` | `0, 52.08, 94, 23.17` |
| `.tk` bar | `0, 82.00, 100, 3.94` | `0, 75.81, 100, 3.94` |
| `.nt` kicker | `95.00, 7.31, 100, 6.08` | `54.51, 5.06, 40.49, 6.07` |
| `.pz` price | `94.00, 16.31, 100, 5.40` | `61.53, 16.31, 32.47, 6.31` |
| `.xt` EXTRA! | `95.00, 34.88, 100, 6.75` | `48.10, 32.68, 47.69, 11.76` |

**Fix:** `bottom`/`right` must be resolved together with the box size
(`y = 100 − bottom − h`, `x = 100 − right − w`), and when only `right`/`bottom` is given the
size must come from the element's intrinsic content (F3), then be laid out from that edge.
Code: `_partial_box()` L463–512.

#### F3. No shrink-to-fit, no flex/grid item sizing
Anything without an explicit `width` inherits the parent's width, including inline-blocks
and flex children.

| element | parsed w | truth w |
|---|---|---|
| `.lv` badge | 100.00 | 22.02 |
| `.tg` (BREAKING / DEVELOPING / LIVE) | 94.00 | 30.25 / 35.90 / 16.44 |
| `.tk b` | 100.00 | 16.68 |
| `.pn small` | 88.00 | 50.44 |

`resolve_box()` also gives static children the parent's **x**, ignoring the parent's padding
(`li` parsed at `x 2.00` vs truth `11.00`).

**Fix:** implement intrinsic width for inline-block / inline-flex / flex items (text width
via font metrics + padding + border), or delegate to the measurement pass (§6).

#### F4. Duration: `data-e="99"` sentinel + ignored UI setting
The page's last panel uses `data-e="99"` (a "never hide" sentinel). `main()` treats it as a
real end time and stretches **all** stages to 99 s; `write_project()` then writes
`"duration": DURATION_MS` (global) instead of `stage["duration"]`. The UI's *Duration (s)*
field is dropped by the server: `handle_html_preview` / `handle_html_projects` never forward
`durationMs`. `--duration-ms` only sets the run-wide `DURATION_MS` (used for fade timing and
written as the composition duration), and the per-stage `data-d` is computed but never used.

**Fix**
- Treat `data-e` greater than the stage duration (or ≥ 90 s) as "open ended".
- Derive the stage duration in this order: `data-d` → explicit `--duration-ms` → page JS
  constant (`const D=10000`) → max real `data-e`.
- Forward `durationMs` from `html-to-layers.html` → both server handlers → CLI.
- Write the **stage** duration into the composition.
- Code: `main()` L2061–2071, `extract_stage()` L1292, `write_project()` L1943,
  `image-to-layers-server.py` L713/L753, `html-to-layers.html` L330.

#### F5. Wrong photo becomes the stage background
`extract_background()` accepts any descendant whose class is in
`("cam","abs","photo","image","im","bgb","world","bgp","nvi")` **regardless of size**. On
stage 3 that matches `.ph .im` — the photo *inside the newspaper's photo window* — so the
cream paper `#efe7d4` stage background is discarded and replaced by the photo; the `.ph`
window is then emitted as an empty frame with no photo in it.

**Fix**
- Prefer the stage's own `background`/`background-color` (paint a solid SVG when it is a
  colour) over any descendant image.
- A descendant only becomes the stage background when it (a) covers ≥ ~90 % of the stage
  after clipping and (b) is not inside an `overflow:hidden`/`clip-path` ancestor.
- Otherwise emit it as an image layer clipped to the window (the harness already records the
  clip box: `{"x":6,"y":45.56,"w":88,"h":21.37}`).
- Code: `extract_background()` L779–822, `_own_background_url()` L1158.

### P1 — visible fidelity loss

#### F6. `%` lengths resolve against the stage instead of the containing block
`.tk b { height: 100% }` becomes `h 100` (full stage) instead of 100 % of the 3.94 % bar —
visible as the "NOW" layer covering the whole stage. Same class of bug for
`width: 100%`, `padding: 5%`, `left: 50%`.

**Fix:** thread the containing-block size through `length_pct()` / `_partial_box()` /
`resolve_box()`; only the stage itself uses 100 % = stage. Code: L421–444.

#### F7. Padding, borders and margins are ignored in text boxes
`.hd` has `padding: 2.5cqw 5cqw`, `.sb` `1.5cqw 5cqw`, `.tg` `.8cqw 3cqw`, `.pn` `4cqw 5cqw`.
The extractor places the text at the element's border box, so copy sits ~5 cqw too far left
and boxes are far too short:

| layer | parsed h | truth h |
|---|---|---|
| `.hd` (Cyclist…) | 8.51 | 15.56 |
| `.sb` (Rabbie's Eggs) | 2.56 | 4.20 |
| `.pn` panel | 22.19 | 45.02 |
| `.bd` | 7.03 | 10.26 |

**Fix:** either emit the shape at the border box and the text at the *content box*
(padding-inset), or add `padding` to the layer and honour it in the renderer. Shapes need the
border box; text needs the content box. Also read `margin-top` for stacked children
(`.bd i` parsed at `y 74.25`, truth `76.64`).

#### F8. Text measurement/line wrapping is guesswork
`estimate_height()` assumes `char_px = font-size × 0.52` and one font for all copy. Result:

| layer | parsed lines | real lines |
|---|---|---|
| `.mh` (9.4 cqw Playfair) | 2 | 1 |
| `.hl` (12.5 cqw Playfair, uppercase) | 3 | 4 |
| `.hd` (7 cqw Oswald) | 2 | 3 |

It also reads `font-size` from `computed()` in `resolve_box()` but from `inherited()` in
`make_layer()`, so `li` layers get `font.sizePct 4.3` with `h 1.00` (should be 3.91).

**Fix:** one style source (`inherited()`), and real wrapping (measure with the actual font,
or delegate to the browser). Code: `estimate_height()` L581, `resolve_box()` L643,
`make_layer()` L896.

#### F9. Content-driven heights / bottom-anchored blocks are not solved
`.l3` is `bottom: 44cqw` with height determined by its children; `.pn` height is content +
padding. Both need “measure children → place block”. Today the block's top is the bottom edge
(`F2`) and the children are stacked on top of that, so the whole lower third of every reel is
displaced.

#### F10. No clipping/overflow chain
`.ph { overflow:hidden; clip-path:inset(0) }` clips the photo; `.tk { overflow:hidden }` clips
the 455 %-wide marquee. The extractor emits neither a clip nor a cropped image: the ticker
text becomes a 100 %-wide line starting at `x 0` (the browser's marquee span is 455 % wide,
clipped to the bar, and starts after the `NOW` tag at `x 16.68`), and the marquee string is
duplicated in the layer text (the page repeats it for the CSS animation).

**Fix:** clip image/shape layers to the nearest clipping ancestor; clip text to the parent
box and offset it by the inline predecessor's width; de-duplicate a repeated marquee run.

#### F11. Timing is flat and does not inherit
- `li[data-s="2"]` has no `data-e`; the parser emits `end: null`, so the list keeps showing
  after `.pn[data-e="9.5"]` hides at 9.5 s. Descendants must intersect with the ancestor
  window.
- `data-s="0" data-e="99"` on `.pp` is a sentinel (F4) and produces a 99 s keyframe set.
- The 300 ms fade is added everywhere although the page switches instantly.
- White flash (`.flash`, 0.1–0.3 s), scanlines (`.scan`), and the loop blackout (`.fade`) are
  overlays that are currently dropped by accident (full-bleed) rather than by decision.

Code: `find_timing()` L764, `_timing_keyframes()` L1115, `SKIP_CLASSES` L69.

#### F12. Background motion and filters are replaced by a generic Ken Burns
The page pans the photo with a JS-driven custom property:

```css
.n1 .im { background-image: var(--a);
          background-position: calc(15% + var(--p)*50%) 50%;
          transform: scale(calc(1.05 + var(--p)*.08)) }
```

Measured: `.im` is `105 × 105` at `(-2.5,-2.5)` at `p=0` and `113 × 113` at `(-6.5,-6.5)` at
`p=1` (stage 1), `70 % → 25 %` for stage 2. The extractor ignores `background-position`
entirely and writes the fixed `-2 → 104 → 110` zoom, so the composition shows a centred crop
that neither starts nor moves where the reel does. `.ph .im` additionally has
`filter: grayscale(1) contrast(1.35) sepia(.35)`, which is dropped.

**Fix:** parse `background-position`/`background-size`/`transform:scale` and turn the
`--p`-driven values into x/y/w/h keyframes; apply CSS filters to the extracted bitmap with
Pillow (and cache per filter string).

#### F13. Transform support is partial
Only `translate()` and `rotate(deg)` are read; `scale()` is ignored, so `.bk`
(`scale(1.6)` → `1`), `.xt` (`scale(2.5)` → `1`), `.pp` (540° spin-in) and the photo zoom are
all wrong. The angle itself is usually right, but it is applied to the wrong box: `.xt` is
rotated as a 100 %-wide bar instead of a 47.69 %-wide tag.

#### F14. Missing CSS features that these pages rely on
- sibling combinators `+` / `~` → `.mh ~ i` (the masthead rule) is not extracted at all;
- pseudo-elements → `.lv::before` (live dot), `.pn li::before` (“✔ ”) missing;
- per-side borders → `.hd { border-left: 1.6cqw solid var(--pink) }` dropped (only the
  `border` shorthand is parsed);
- `calc()` → bar width, background position, transforms;
- gradients → `parse_colour()` returns the default `#ffffff` for any gradient, so gradient
  boxes would be painted solid white (`extract_container_shape()` L1190 has a
  `if not fill and "gradient" in …` branch that can never run);
- `@media` blocks are skipped entirely (`split_rules()` L216).

#### F15. Layer names are hard-coded to a different template family
`CLASS_HINTS` / `extract_container_shape()` name `.hd` “Banner”, `.sb` “Shape”, `.pn`
“Badge” (it is the whole menu panel), `.bd` “Board” (it is the byline block). This map was
written for a handful of hand-authored templates (Nonna, r1/r2 spotlight/route) and misfires
here. It also collides with `SKIP_CLASSES` (`"bar"`), which will silently drop a legitimately
named component on another page.

**Fix:** derive names from role + content ("LIVE badge", "Headline", "Ticker", "Menu panel",
"Photo window"), and keep the class map only as a hint with a generic default.

#### F16. Text semantics: inline runs, dynamic copy, duplicates
- Parent/child duplication: `.bd` and its `<i>` overlap at the same y (parsed `74.25` twice)
  because a child's y does not account for the parent's own text (F7).
- The `.tc` timecode (“08:14:29”) is injected by JS, so the static HTML has no text and the
  layer is missing. Same for any JS-driven copy.
- `<br>`-separated kickers lose their structure (`SINGL-END NEWS` / `REC` come out as one
  string) although the newline is kept in `text`.
- Inline runs are split into separate layers instead of merged into one paragraph
  (`<p>Hello <b>world</b></p>` ⇒ two layers, and the parent's string loses “world”).

#### F17. `estimatedBox` is dead and no warnings fire
`resolve_box()` sets `_estimated` only when the parent box is missing, so
`meta.estimatedBox` is `false` for every emitted layer, `warnings` is `[]` for all three stages,
and the UI's amber “estimated” outline / warning list never appears — even though 33 of 34
boxes are wrong. There is also no warning for layers outside the stage or at `opacity 0`.

**Fix:** mark a box estimated whenever any side came from a parent/estimate instead of an
explicit CSS length; warn on off-canvas boxes, zero-opacity layers and empty stages.

### P2 — UI / plumbing

#### F18. Preview and generated project diverge
- The preview drops the `html-bg` layer (`_stage_preview()` L1988) but the composition keeps
  it — with different keyframes (Ken Burns) than the static preview.
- The scrubber range comes from `parsed.stages[0].duration` (`renderStages()` L495), while
  `showDetail()` resets it to the selected stage; with mixed durations the shared time is
  ambiguous.
- `applyTime()` applies keyframe opacity (the working tree already fixed the missing
  `activeKf.opacity` branch), but the keyframes themselves carry the parsed `opacity: 0`, so
  a layer reads as “visible” at `meta.start` and still renders at `0.01`; the blank cards
  A/B are F1 showing through the preview.
- The preview does not honour padding, so text is drawn against the shape edge.

#### F19. Server/UI wiring
- `durationMs` is sent by the UI (`options()` L330) and ignored by both handlers.
- “Download remote images” (`fetchRemote`) is sent and ignored: neither handler passes
  `--fetch-remote`, so the checkbox is a no-op and remote images are always kept as links.
- “Open in Studio” points at `/studio-v2.html`, which **404s** on this checkout
  (`curl http://127.0.0.1:8008/studio-v2.html` → 404).
- `handle_html_preview` clears its temp dir after the run, so preview image URLs that point
  to local files (`file://` or temp-relative) can break in the UI; stage images are data URLs
  here, but not for every example.
- Segmentation passes the whole stage through `--sam-auto` without a scene hint derived from
  the HTML, so cut-outs do not line up with the authored elements.

#### F20. Parser robustness details
- `parse_letter_spacing()` divides px by 16 instead of by the font size, so
  `letter-spacing: .4cqw` over/under-states the em value for non-16 px text.
- `!important` is stripped and not given cascade priority.
- `z-index`/stacking contexts are ignored; layer order is DOM order (usually right here, not
  in general).
- `@media` rules are dropped, including the `prefers-color-scheme` overrides that change
  `--bg`/`--ink` — the tool always extracts the light theme.
- `stack_children()` only understands `display:flex; flex-direction:column`; grid and row
  flex layouts fall back to “parent box”.
- `SKIP_CLASSES` matches by bare class name (`bar`, `safe`, `fade`, `vg`, `sp`, `bgb`, `mr`,
  `rg`), so a page that uses one of those names for real content silently loses it.

## 5. Fix plan

### P0 — make the output truthful (1 PR)
1. **Active-state pass** (F1): apply `.on` variants; stop baking entry transforms/opacity.
2. **Edge anchoring + intrinsic size + containing-block %** (F2, F3, F6).

## 6. Architectural choice (needs a decision)

**Option A — measure, don't guess (recommended).**
Run each stage through headless Chrome once (`getBoundingClientRect` + `getComputedStyle`
with `.on` applied, plus clip chain and pseudo content), then build layers from the measured
geometry. `tools/measure-html-chrome.py` already proves the approach end-to-end with no new
package dependencies (it only shells out to Chrome). It fixes F1, F2, F3, F6, F7, F8, F9, F10,
F13 and F16 in one move, turns F14 from a layout guess into a paint decision, and gives the
tests a real oracle. Python keeps what it is good at: choosing which nodes are
layers, timing, naming, image materialisation, SVG shapes, segmentation, composition output.
Fallback: when Chrome is unavailable, keep today's estimator (with P0 fixes) and label the
result `estimated`.

**Option B — keep patching the interpreter.**
Cheaper now, but a hand-written CSS subset will keep diverging (F6–F14 are all “implement a
layout engine”). Realistically it can reach ~80–90 % on these simple templates, not the
“100 % reflective” goal, and every new example page will find a new gap.

**Recommendation:** P0 fixes + Option A. Keep the Python estimator as the no-Chrome fallback,
and make the fixture-based comparison the acceptance gate for every example in
`html-examples/`.
